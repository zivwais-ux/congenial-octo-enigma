# גדות סטודיו · אישור עבודות גרפיות (סקיצה)

דמו לחיץ של מערכת שמחליפה את המיילים, הוואטסאפ וה-Teams בתהליך אישור עבודות גרפיות במחלקת העיצוב:

**מעצב מעלה ← מאשר מקבל התראה ← הערות על הפיקסל ← גרסה מתוקנת ← אישור ← ארכיון.**

> זה פרוטוטייפ בלבד: אין שרת, אין מסד נתונים ואין התחברות. הכל רץ בדפדפן.
>
> - **נתוני דמה:** 6 משתמשים, 4 פרויקטים ו-12 עבודות. התמונות נוצרות בקוד, בלי תלות באינטרנט.
> - **שמירה:** כל שינוי נשמר ב-`localStorage`, וקבצים שמעלים נשמרים ב-IndexedDB, כך שהכל נשאר גם אחרי רענון.
> - **רק בדפדפן הזה:** הנתונים קיימים רק בדפדפן שבו עובדים. מחשב אחר, או חלון גלישה בסתר, יתחילו מנתוני הדמה.

## מה יש בפנים

- **מסך ראשי לכל תפקיד:**
  - למאשר: תור "ממתין להחלטה שלך" והעבודה הדחופה ביותר בראש המסך.
  - למעצב: "חזרו אליך לתיקונים" למעלה.
  - בשניהם: תצוגת טבלה או תמונות, וסינון לפי סטטוס, פרויקט וחיפוש.
- **מסך עבודה בסגנון Frame.io:**
  - במה כהה שבה העבודה במרכז.
  - הערות מוצמדות וממוספרות: קליק על נקודה בעבודה פותח הערה במקום הזה.
  - מעבר בין גרסאות.
  - השוואה זו לצד זו, או במצב "תריס" שגוררים מעל התמונה.
  - ציר פעילות מלא.
- **החלטות:** מאושר / נדרשים תיקונים / נדחה. תיקונים ודחייה מחייבים הסבר. במובייל הכפתורים קבועים בתחתית המסך.
- **התראות:** פעמון עם רשימה מלאה. לכל התראה יש תגית שמדמה את הערוץ שאליו "נשלחה" (מייל / Teams / וואטסאפ).
- **רצף סקירה למאשר:** "2 מתוך 4 בתור" בראש מסך העבודה, מקשי <kbd>J</kbd>/<kbd>K</kbd>, ואחרי החלטה מוצג "הבא בתור" (<kbd>Enter</kbd> עובר אליה). כשהתור מתרוקן מוצג סיכום של הסקירה.
- **זום ומסך מלא:** פלוס ומינוס, 100%, גלגלת עם Ctrl/⌘, צביטה במובייל, גרירה של תמונה מוגדלת ומסך מלא. אפשר להוסיף הערות גם כשהתמונה מוגדלת.
  - <kbd>←</kbd>/<kbd>→</kbd> עוברים בין גרסאות.
  - במובייל יש כפתור צף שקופץ להערות.
- **שרשורי תגובה:** אפשר להגיב לכל הערה. מעצב יכול לענות ולסמן "טופל" בפעולה אחת, וכותב ההערה מקבל התראה.
- **ביטול פעולה:** אחרי החלטה, סימון "טופל" או מחיקת הערה, ההודעה שמופיעה כוללת כפתור "ביטול".
- **"כך זה מגיע אליהם":** כשנשלחת התראה למשתמש אחר, מוצגת הדמיה של ההודעה בערוץ שלו: בועת צ'אט לוואטסאפ, כרטיס ל-Teams או תצוגת מייל. אפשר לכבות את ההדמיה בתפריט המשתמש.
- **מסך פתיחה:** בכניסה הראשונה ואחרי איפוס בוחרים צד: "להיכנס כמאשר/ת" או "כמעצב/ת", או מתחילים את תסריט ההדגמה. קישור ישיר לעבודה נפתח בלי מסך הפתיחה.
- **"מה תוקן":** כשמעלים גרסה חדשה מוצגות ההערות הפתוחות כצ'קליסט. ההערות שמסמנים ממלאות את שדה "מה השתנה" ונסגרות כ"טופל".
- **אימות תיקונים:** על הגרסה החדשה מוצגים בקו מקווקו הסימונים מהגרסה הקודמת: ירוק אם טופל, כתום אם עדיין פתוח. בפאנל ההערות יש קבוצה "מגרסה 1".
- **צ'קליסט מותג באישור:** לוגו, צבעים, הגהה ומידות. הצ'קליסט לא חוסם את האישור, ומה שסומן נשמר בציר הפעילות ובארכיון.
- **תצוגת לוח:** תצוגה נוספת בדשבורד (מעבר לטבלה ולתמונות) עם עמודה לכל שלב.
  - מעל הלוח: זמן אישור ממוצע, ממוצע סבבים לעבודה, והעבודה שמחכה הכי הרבה זמן.
  - במובייל העמודות נגללות לרוחב.
- **ארכיון:** כל העבודות המאושרות מקובצות לפי פרויקט, עם כל הגרסאות וקובץ המקור להורדה, וחיפוש לפי שם, פרויקט, מעצב, תאריך או שם קובץ.
- **חיפוש מהיר:** <kbd>⌘K</kbd> / <kbd>Ctrl+K</kbd> או <kbd>/</kbd>, לקפיצה לכל עבודה או פעולה.
- **תסריט ההדגמה:** חמשת צעדי התסריט בתוך האפליקציה. כל צעד מחליף לתצוגה של המשתמש הנכון ופותח את המסך, והסימונים מתעדכנים לבד תוך כדי ההצגה.

## הרצה מקומית

דרוש Node.js 18 ומעלה.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # בדיקת טיפוסים ובנייה לתיקייה dist/
```

## פריסה ל-Vercel

אין צורך בהגדרות: Vercel מזהה Vite אוטומטית (Build: `npm run build`, Output: `dist`).
הניווט מבוסס על `#` בכתובת, כך שרענון עובד בכל מסך גם בלי rewrites.

1. ב-Vercel: **Add New → Project**, ובוחרים את הריפו.
2. לוחצים **Deploy**. מכאן כל push ל-`main` מתפרס אוטומטית.

## תסריט ההדגמה להנהלה (5 צעדים, כ-5 דקות)

הכי פשוט לפתוח את **תסריט ההדגמה** (בתחתית סרגל הצד, או בכפתור הרשימה בסרגל העליון במובייל) וללכת לפיו. לפני כל הצגה לוחצים שם **איפוס הדגמה**, ומכינים במחשב תמונה של עבודה ועוד גרסה מתוקנת שלה.

1. **העלאת עבודה** (בתצוגה של נועה לוי, מעצבת)
   גוררים את התמונה מהמחשב, מוסיפים קובץ מקור אם יש, בוחרים מאשר ← **שליחה לאישור**.
   מראים את ההודעה "נשלח ל... לאישור · התראה ב-Teams".
2. **הערות על העבודה ובקשת תיקונים** (בתצוגה של המאשר)
   פותחים את הפעמון. ליד ההתראה מופיעה תגית הערוץ, שממחישה שההתראה תגיע לאן שכבר עובדים. לוחצים עליה ← לוחצים על **שתי נקודות בעבודה** ← **נדרשים תיקונים**.
   *המסר: הערה מדויקת על הפיקסל, במקום "צריך להזיז קצת את הדבר הזה" בוואטסאפ.*
3. **גרסה 2** (בתצוגה של המעצבת)
   ההערות הממוספרות מחכות על העבודה. מסמנים "טופל" ← **העלאת גרסה 2**.
4. **השוואה ואישור** (בתצוגה של המאשר)
   **השוואה**: זו לצד זו, ואז במצב **תריס** ← **מאושר**.
5. **ארכיון**
   מחפשים את העבודה, מראים את כל הגרסאות וקובץ המקור, ו**מרעננים את הדף** כדי להראות שהכל נשמר.
   *המסר: סוף הבלגן בתיקיות.*

טיפ: מסך העבודה עובד גם בטלפון. כדאי להראות שמאשרים גם מהנייד.

## בדיקת נתונים (Zod)

מבנה הנתונים מוגדר פעם אחת, ב-`src/schema.ts`, בעזרת הספרייה [Zod](https://zod.dev). הסכמה הזו משמשת לשלושה דברים:

- **טיפוסים:** הטיפוסים של TypeScript ב-`src/types.ts` נגזרים ממנה אוטומטית, כך שאין שתי הגדרות שיכולות לסטות זו מזו.
- **בדיקה בטעינה:** כשהאתר נפתח, הנתונים השמורים בדפדפן נבדקים מול הסכמה. נבדקים גם השדות וגם ההפניות בין הרשומות (למשל, שעבודה מפנה לפרויקט ולמשתמש שקיימים). אם משהו פגום, ההדגמה מתחילה מחדש מנתוני הדמה ומוצגת הודעה, במקום מסך שבור. פירוט הבעיה נרשם בקונסול.
- **בדיקה בזמן פיתוח:** כל שינוי בנתונים נבדק מול הסכמה, וכל פעולה שיוצרת נתונים לא תקינים מסומנת מיד בקונסול. הבדיקה הזו לא רצה באתר המפורסם.

במערכת האמיתית, אותה סכמה תבדוק גם את מה שחוזר מהשרת.

## מבנה הקוד

```
src/
  schema.ts                מבנה הנתונים ובדיקתו (Zod)
  types.ts                 טיפוסים שנגזרים מהסכמה
  data/                    נתוני דמה ותמונות SVG שנוצרות בקוד
  store/                   state, שמירה ל-localStorage, פעולות, קבצים ב-IndexedDB
  lib/                     סטטוסים, תאריכים, ניסוחים, תסריט ההדגמה
  pages/                   סקירה, מסך עבודה, העלאה, ארכיון
  components/viewer/       במה, הערות מוצמדות, השוואה ותריס, החלטות, ציר פעילות
  components/layout/       סרגל צד, סרגל עליון, התראות, חיפוש מהיר, תסריט ההדגמה
  components/ui/           כפתורים, תגיות, מודאלים ושאר אבני הבניין
```

## מה יידרש למערכת אמיתית

- **התחברות:** חשבונות ארגוניים (למשל Microsoft 365) במקום החלפת משתמש.
- **שרת ואחסון:** שרת ומסד נתונים במקום localStorage, ואחסון קבצים במקום IndexedDB.
- **התראות:** שליחה אמיתית במייל, ב-Teams ובוואטסאפ, לפי העדפת כל משתמש.
- **הרשאות:** מי רואה אילו פרויקטים, ומי רשאי לאשר.
- **הערות על PDF:** תמיכה בהערות מוצמדות גם בקבצי PDF.
