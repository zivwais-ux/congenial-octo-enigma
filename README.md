# גדות · אישור עבודות (פרוטוטייפ)

דמו לחיץ לאפליקציה שמחליפה את המיילים, הוואטסאפ וה-Teams בתהליך אישור עבודות גרפיות במחלקת העיצוב:
מעצב מעלה עבודה ← מאשר מקבל התראה ← מאשר מאשר או מבקש תיקונים על גבי התמונה ← מעצב מעלה גרסה חדשה ← עבודה מאושרת עוברת לארכיון.

**זה פרוטוטייפ בלבד:** אין שרת, אין מסד נתונים ואין התחברות. הכל רץ בדפדפן:

- נתוני דמה (6 משתמשים, 4 פרויקטים, 12 עבודות) נוצרים בקוד, כולל תמונות SVG, בלי תלות באינטרנט.
- כל שינוי נשמר ב-`localStorage`, וקבצים שמעלים נשמרים ב-IndexedDB, כך שהכל נשאר גם אחרי רענון.
- הנתונים נשמרים **רק בדפדפן שבו עובדים**. מחשב אחר, או חלון גלישה בסתר, יתחילו מנתוני הדמה.
- "איפוס דמו" (בתפריט החלפת המשתמש) מחזיר את נתוני ההתחלה ומוחק קבצים שהועלו.

## הרצה מקומית

דרוש Node.js 18 ומעלה.

```bash
npm install
npm run dev        # http://localhost:5173
```

בדיקת טיפוסים ובנייה לייצור:

```bash
npm run build      # הפלט בתיקייה dist/
npm run preview    # הגשה מקומית של הבנייה
```

## פריסה ל-Vercel

אין צורך בהגדרות מיוחדות:

1. מעלים את הריפו ל-GitHub.
2. ב-Vercel: **Add New → Project**, ובוחרים את הריפו.
3. Vercel מזהה Vite אוטומטית (Build: `npm run build`, Output: `dist`). לוחצים **Deploy**.

או מהטרמינל: `npx vercel` (ובפעם הבאה `npx vercel --prod`).

הניווט באפליקציה מבוסס על `#` בכתובת (HashRouter), כך שרענון בכל מסך עובד גם בלי הגדרות rewrites.

## תסריט דמו להנהלה (5 צעדים, כ-5 דקות)

לפני ההצגה: פתחו את האפליקציה ולחצו **איפוס דמו**. הכינו במחשב תמונה אמיתית (PNG/JPG) של עבודה, ועוד גרסה מתוקנת שלה.

1. **"ככה זה נראה היום מצד המאשר"**
   נכנסים כ**מיכל אברהם** (מנהלת המחלקה). מראים את "מחכה לאישורי", ממוין לפי דדליין, עם העבודה שבאיחור מודגשת באדום ומונה ההתראות בפעמון.
   *המסר: מקום אחד לראות מה מחכה, במקום לחפש במיילים.*

2. **מעצב שולח עבודה**
   מחליפים ל**נועה לוי** (החלפת משתמש למעלה) ← **העלאת עבודה** ← גוררים את התמונה מהמחשב, ומוסיפים קובץ מקור אם יש. בוחרים פרויקט, ממלאים דדליין ובוחרים את מיכל כמאשרת ← **שליחה לאישור**.
   מראים את ההודעה "נשלח למיכל אברהם לאישור · התראה ב-Teams".

3. **המאשרת מגיבה על גבי התמונה**
   חוזרים ל**מיכל** ← פותחים את הפעמון. ליד ההתראה מופיעה תגית הערוץ (Teams/מייל/וואטסאפ), שממחישה שבמערכת האמיתית ההתראה תגיע לאן שכבר עובדים. לוחצים על ההתראה.
   לוחצים על **שתי נקודות בתמונה** וכותבים הערה בכל אחת ← **נדרשים תיקונים** (חובה לכתוב הסבר) ← שליחה.
   *המסר: הערה מדויקת על הפיקסל, במקום "תזיז קצת את הדבר הזה למעלה" בוואטסאפ.*

4. **המעצבת מתקנת ומעלה גרסה 2**
   מחליפים ל**נועה**. בדשבורד העבודה מופיעה למעלה, תחת "נדרשים תיקונים". פותחים אותה ורואים את ההערות הממוספרות על התמונה. מסמנים אותן "טופל" ← **העלה גרסה חדשה** ← מעלים את הגרסה המתוקנת.

5. **השוואה, אישור וארכיון**
   מחליפים ל**מיכל** ← פותחים את העבודה ← **השוואה**: גרסה 1 מול גרסה 2 זו לצד זו, עם ההערות שהיו על גרסה 1 ← **מאושר**.
   עוברים ל**ארכיון**: העבודה מופיעה תחת הפרויקט שלה, עם כל הגרסאות וקובץ המקור להורדה. מחפשים אותה לפי שם.
   לסיום, **מרעננים את הדף** ומראים שהכל נשמר.
   *המסר: סוף הבלגן בתיקיות. כל עבודה מאושרת, עם ההיסטוריה שלה, במקום אחד.*

טיפ: מסך העבודה עובד גם בטלפון, עם כפתורי ההחלטה בתחתית המסך. כדאי להראות שמאשר יכול לאשר גם מהנייד.

## מבנה הקוד

```
src/
  types.ts                 מודל הנתונים (User, Project, Item, Version, Comment, Notification)
  data/seed.ts             נתוני הדמה
  data/placeholders.ts     תמונות SVG שנוצרות בקוד
  store/                   state, שמירה ל-localStorage, פעולות, ושמירת קבצים ב-IndexedDB
  pages/                   דשבורד, מסך עבודה, העלאה, ארכיון
  components/viewer/       תצוגה מקדימה, הערות מוצמדות, השוואה, החלטות, ציר זמן
  components/layout/       כותרת, החלפת משתמש, פעמון התראות, ניווט במובייל
```

## מה יידרש למערכת אמיתית

- **התחברות:** חשבונות ארגוניים, למשל Microsoft 365, במקום החלפת משתמש.
- **שרת ואחסון:** שרת ומסד נתונים במקום localStorage, ואחסון קבצים במקום IndexedDB.
- **התראות:** שליחה אמיתית במייל, ב-Teams ובוואטסאפ, לפי העדפת כל משתמש.
- **הרשאות:** מי רואה אילו פרויקטים, ומי רשאי לאשר.
- **הערות על PDF:** תמיכה בהערות מוצמדות גם בקבצי PDF. בפרוטוטייפ יש ב-PDF רק הערות כלליות.
